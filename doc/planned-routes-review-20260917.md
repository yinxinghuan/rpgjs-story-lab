# 生成前的探索安排：实证与边界

## 本轮实现

仅新建 v3 委托在创建时保存 `explorationRoute`。按旅程 ID 稳定分配原地查阅、照相馆借阅、洗衣店借阅三条已经支持的路线。模型收到的是路线约束，不收到旅程身份。生成重试、后台重建、刷新不改选；旧旅程没有该字段就维持原有路线。

成套调查的两份内容共享路线；不相容的草稿先进入已有的一次修正，仍不相容则失败。模型负责历史事件与线索，不负责发明未建的通道。路线变化只改变日志的位置和实际查阅路径，没有增加额外结局门槛。

## 验证

- 37 项核心检查通过：创建与旧旅程升级、路线矛盾后的修正/拒绝、任务失败重试与成套草稿恢复、实际位置取证、主线结局门槛、显影旧新旅程兼容。
- `npm run build` 通过，含空间检查、素材哈希和 Worker 启动检查。
- 两批真实合成叙事请求共 18 次，无新媒体请求。原始输出和失败均保留在 `campaign-live-20260917/planned-routes-1.json`、`planned-routes-2.json`。
- 第一批照相馆草稿存在明显因果倒置，复核反馈超长导致无法修正。现已允许对明确拒绝的反馈截短后进入原有一次修正；不放宽通过条件。第二批两条调查分别遵循照相馆与档案室路线。
- 第二批第一条真实内容原样回放到本地主 renderer：档案借条→地下室→院子→街口→照相馆日志→原路返回→整理桌核对通过。前序取信/取证用普通权威行动准备，非从开场完整 UI 通关。使用独立合成数据库，无真实存档。390×844 借条、320×568 日志/核对保存截图于 `_qa/ui/planned-routes-20260917/`；界面在过程中随浏览器语言变成中文，内容保持原英文，因此后段证据是混合语言状态，不能当纯英文整体 UI 验收。

截图限制：工具截图与实际 DOM 尺寸存在缩放差异；320 宽时弹层 DOM 为约296×544、位于12px边距内，但保存图片未正确反映该构图。截图仅保留操作过程，不作为本轮手机视觉合格证明。实际按钮提交/转场/恢复证据有效，真机视觉验收待整合阶段。

刷新后回到同一档案室，原有顺序、两处证据和下一步寻找旧照的目的保持；数据库读取也确认 route=studio-loan-v1、examined=[index,ledger] 与已核对顺序一致。没有新生成请求。

## 内容评审与尚未完成

第二批照相馆样本是路面裂缝调查，历史顺序基本合理，但问题仍可凭常识猜出。档案室样本最后两个安装事件近义重复。两条后续照片规划都被拒绝：第一条复核引用了发现文字而非图像描述的原文；第二条复核错误地把 observationOnly=true 当成拒绝条件。这是后续整链需要修复的具体缺口，不是生成成功。

稳定调度支持“每份旅程可有不同查阅路线”，尚不支持任意动态地图章节，也没有证明完整游戏的内容量和节奏达标。下阶段应修复照片连续性复核后，回到整段委托体验与有后果的探索选择，不继续围绕单一排序题累加步骤。

## 发布状态

只在现有主游戏开发分支推进；正式入口仍关闭。没有生产部署、游戏迁移或新游戏 UUID。UI 本地基线、真实 iPhone/声音与平台整合验收的区别保持。
