# 本地优先的玩法验证

## 目标与发布节奏

优先验证玩家通过地图自由探索推进故事的完整结构，减少依赖用户远程解锁及保持平台窗口前台。本轮线上试玩保留为阶段参照；其后通常本地迭代，阶段交付或必须在线验证才能继续时再发布。

## 日常入口

使用 Node 22.22.2。项目根目录执行 `npm run dev:playtest`，打开 `http://127.0.0.1:5455/`。默认新探索试玩；旅程菜单中折叠的旧版参考通向 `?story=original`。本机两种权威服务维持独立存储，沿用旧存档，不为了测试清空存储。

执行 `npm run test:exploration` 可无前台窗口验证旧街规则、地图连接、物件状态、角色介绍、解谜证据、旅程回执和恢复。执行 `npm test` 扩展到旧版、创作和公共能力回归；部分用例需要允许临时回环 HTTP 监听。测试均使用专门测试数据库。

## 验证边界

| 层级 | 优先方法 | 不代表什么 |
| --- | --- | --- |
| 地图、碰撞、解谜、路线、结局与人物状态 | 本地确定性测试；新增玩法同步增补有意义的行为断言 | 不证明真实画面舒服、出口容易理解 |
| 断线、重复请求、刷新与丢失响应 | 本地 Worker/HTTP 故障注入及隔离测试旅程 | 不证明真实广域网延迟和平台桥接 |
| 人物步态、镜头、触控、对白布局 | 本地真实 renderer 试玩和截图 | 不证明 iPhone 实机或 AlterU 宿主行为 |
| API 部署、资源缓存、公开接口版本 | 必要时直接请求线上接口和实际 bundle | 不需要一概要求解锁 Telegram |
| 平台登录桥接、真实 WebView、iPhone 与平台内输入 | 集中到必要节点做真实应用测试 | 需要可操作窗口时如实记录，不能冒充已通过 |

## 下一轮本地重点

1. 让可见门口与地图连接直观一致，验证往返、绕行和带道具返回后的变化。
2. 完善检查、拿取、使用、归还、交谈的就近行动与短对白，避免测试术语进入产品界面。
3. 在保持已选 B 视角的前提下补齐空间美术与角色活动，逐项验证脚点、遮挡、碰撞、状态图一致性。
4. 扩充能够由玩家发现和选择推进的内容，避免恢复话剧式强制逐幕转场。

当前候选美术未全部正式准入；规则通过不等于玩家理解或美术验收通过。局部开发故障不应让所有工作等待用户解锁。
