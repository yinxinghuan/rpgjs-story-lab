# 新委托主线衔接实证（2026-09-17）

## 结果

在现有游戏加入显式新建的 v3 委托：取信/比对寄存条 → 调查档案 → 在照相馆寻找相关旧照 → 通过真实侧门进入暗房 → 看清照片并决定去向 → 回家。开场、当前目标和片尾回应同一件委托。便笺、抄录、公共摘要及居民帮助仍可选。v1/v2 与旧结局不加新门槛；生产开关仍关闭，未发布线上。

## 实际检查

- 50 项相关核心检查通过：旧链可结束；新链不能在档案完成或图片准备时提前结束；真实匹配后还需决定去向；带走与留下均能完成；来源关联、原件库存、回执及恢复一致。包括旧 campaign、archive、expansion 和 Worker 用例，不声称覆盖全游戏所有情况。
- 完整 `npm run build` 通过，含 TypeScript、空间检查、资源检查及 Worker 启动检查。既有大包/旧引用警告仍在，不据此声称零警告。
- 新建英文 QA 旅程从开场展示完整委托。前 23 次规则行动由 `_qa/commission-playtest-progress.ts` 在专用 QA 库执行，停在已读资料、尚未解答的档案桌；不是完整浏览器通关证据。
- 其后用真实 renderer 操作整理档案 → 地下室 → 院落 → 街口 → 照相馆 → 暗房 → 平台生成 → 拼合 → 留下原件 → 街口回家。生成时离开暗房并刷新，返回后同一任务完成。一次平台媒体任务，未重试；本轮没有新文字模型调用。档案为合成历史，照片规划复用此前同历史的真实文本样本，因此不是整条从零实时生成的旅程。
- 390×844 检查开场、档案收尾和寻找旧照；320×568 检查照片取舍、当前目标、自然出口及片尾。截图在 `_qa/ui/commission-20260917/`。测试浏览器语言与视口临时覆盖已恢复。
- 最后只读核验持久头部：v3、照片与档案关联、`photoChoice=leave`、没有照片库存、finale complete；片尾既记录委托完成，也记录照片留在暗房。见 `commission-media-20260917/result.json`。这仅表示该合成旅程结束，不表示项目总目标完成。
