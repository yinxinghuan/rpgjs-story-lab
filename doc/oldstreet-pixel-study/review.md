# 修表铺像素一致性候选 · 2026-09-15

## 入口与范围

- 候选：`http://127.0.0.1:5455/?shop_art=pixel`
- 原版：`http://127.0.0.1:5455/`
- 两个入口使用同一旅程；只改变呈现，不复制或覆盖存档。正式默认仍是原版，本轮不发布线上。
- 独立操作测试在 5456 的新建旅程进行，未替用户执行 5455 的剧情行动。

## 原因及处理

原地板提示含 painterly pixel-art，细木纹/噪点缺乏像素簇；抽屉 .16 倍显示、地板被裁切后非等比填充，而人物使用另一个粒度体系，分别生成的素材并未统一有效像素和轮廓。

本轮使用平台公共媒体服务生成：448×832 地板、1536×768 抽屉三态、1024×1024 小格三态及记录册。地板整张等比 .5 放入 224×416 世界单位，叠在 #aa8452 底色上以 .55 不透明度降低对比；家具采用约 .96–1 世界单位的像素目标。提示规格不代表真实输出已经是精确网格或限定色数。

保留平台原始图、请求 ID、task ID 和哈希。后处理只去背景和限定家具所在范围，不重画物品。抽屉原图夹带两个人物，裁剪 y190..502 排除；小格首轮为等距视角且空柜丢门，明确拒绝，第二轮矩形顶面用于候选。

## 运行与验证

真实 RPG-JS renderer 使用同一身体碰撞、脚点、门连接、寻路、跟随相机与权威状态。小格图案由 letter-unlocked / letter-taken 决定，抽屉继续由 drawer-open / lens-taken 决定。记录册是独立事件，不烘焙进地板。

- 实际观察 1280×720 初版背景过强；调整不透明度后在约 365×676 窄屏复看。
- 通过实际门进入修表铺、走近抽屉、移开空盒、拿放大镜，三种抽屉状态与物品库存一致；未用状态注入。记录册与锁闭小格均正确显示，旧占位矩形不再同时渲染。
- 在外部访客栏存在时检查页面可载入，随后通过扩展自带 Close 按钮关闭，按无访客栏构图检查人物、物件与操作区。未改动生产 guest-shell。
- 窄屏样本不等于 320×568 / 390×844 精确尺寸验收，也不等于 iPhone 或 AlterU 实机通过。
- 小格开放/取空的图集已目视检查与接入权威事实，但本轮未再次走完借钥匙路线实拍这两态。

## 未通过项

候选准入状态：**仅供可操作风格比较，非生产美术定版**。

1. 各帧桌面木纹和轮廓略有变化；要避免状态切换时纹理跳动，需要下一轮使用固定基底和局部状态编辑。
2. 柜门闭合态与打开态铰链侧不完全一致，原始生成仍有连续性问题。
3. 地板虽然减少噪点并降低对比，但像素网格与家具、人物尚非机械一致。
4. 房间仍缺静态墙面、环境识别和合理布置，不宣称完整修表铺美术已经完成。
5. 主角像素细节比新家具复杂；最终颗粒、线宽需要以合成画面判断，而非仅靠强调 pixel art。

不因素材文件生成成功就批量扩展其他场景。下一轮先解决上述连续性和合成一致性，再决定是否替换默认基准。
