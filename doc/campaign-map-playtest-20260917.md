# 动态材料主线：地图试玩与 Worker 接入

## 范围

本记录属于第二阶段。内容生产使用程序提供的合成材料；实际游戏、RPG-JS renderer、地图行动、任务、存档与结局规则保持原实现。没有调用真实模型或媒体服务，不据此证明生成内容的质量、不同旅程的多样性或45–60分钟体验已完成。线上版本未更新。

## 实际地图试玩

通过 `_qa/campaign-playtest-server.ts` 启动原游戏的本地适配器，数据库独立位于 `.data/campaign-map-playtest-20260917`，关闭所有真实模型入口。没有注入已完成存档或直接设置任务事实。

应用内浏览器中，从街口依次经照相馆、屋顶、工棚借钥匙，开院落门闩，到修表铺解锁取信。在寄存记录处准备材料，收起后通过普通输入「查阅寄存记录」读取同一实例。先选错误的工坊维修记录，得到不匹配反馈；再依据两道刻痕与麻绳选择街道修缮记录。

随后到洗衣店借车，搬开院落箱组，进入地下室。取走旧照片夹后仍可查看主线材料。纸袋准备后刷新，再读到基于已选记录的修桥便条；选择把原件留在旧街。发现页保留线索、三条记录、选择与材料正文；背包没有原件。最后从街口离开，尾声明确显示「你向家人转述了材料里的发现，原件仍留在旧街」。刷新后相同后果仍存在。

只读检查该隔离数据库：旅程版本24、结局complete、trace选择第3条、parcel observed=true/disposition=leave；两个任务均ready、attempt=1，后段context.previous对应街道修缮。过程中的刷新没有重生成。未读取真实玩家数据、账号或能力令牌。

## 试玩发现与修正

- 材料就绪后原本先「查看」再「阅读」，第一步没有有意义的选择。改成「阅读材料」一次提交准入和观察，随后才选择记录或取舍；没有替玩家作决定。已存在但尚未观察的兼容实例仍可单独阅读。
- 取走旧照片夹会让资料架看起来空了，即使主线原件仍留在那里。资料架现在分别呈现照片夹和主线材料，两件物品按各自状态隐藏。复用已有准入图集，没有新增生图。实际同一旅程刷新后，留下的材料仍可见。
- 照片与材料同时存在的双图层已做状态测试；实际地图截图验证的是取走照片、留下材料状态，不能扩大成所有排列的视觉验收。

材料组件夹具另外确认：准备→查询中断→重新连接→就绪→阅读，直接出现三条记录，不再经过空阅读步骤。320宽已检查可访问树中选项和关闭入口；本次不把未保留的截图当成新的320视觉证据。较早完整小屏检查仍见 `material-interaction-ui-20260917.md`。

## 正式后台代码接入（本地验证）

同一 Worker 的旧街路由已支持携带新旅程配置、查询campaign能力、准备/查询trace及parcel；任务通过现有Durable Object的waitUntil继续，草稿保存在该对象原数据库，权威准入仍要求玩家到对应物件旁阅读。开发服务和Worker共用准备操作，不维护另一套状态规则。

`OLD_STREET_CAMPAIGN_RELEASED=false`保持：本地通过显式注入生产器测试正式后台代码；尚未对线上玩家开放新主线。旧旅程不加门槛、原规则和旧内容保留。真实内容及完整主线验收后再集中开启发布。

新增Worker整合测试覆盖一条代表路线：幂等新旅程登记；准备期间正常走到街口；完成任务不移动或推进玩家；重开数据库后复用同一草稿；后段输入继承实际选中记录；合成失败不会自动重试，显式重试成功；取舍回执重放；结局重开恢复。另一项覆盖默认能力关闭与旧旅程语义。没有重复遍历全部路线。

验证：`old-street-worker.test.ts`、`old-street-campaign.test.ts`、`old-street-photo-shelf.test.ts`共23项通过。首次运行有两项旧能力响应断言未包含新增的campaign=false，更新合同预期后复跑通过；不是运行规则失败。完整构建通过，9场景/27资源SHA检查与Worker启动检查通过；公开凭据扫描零命中。
