# 屋顶底片寻回 · 本地实证

本轮把完成旧照之后的一条发现接到实际空间操作：翻看背面归档标记 → 屋顶选择木板 → 跨过破损处 → 开柜取底片 → 带回家或交回照相馆。只为新建 v3 旅程启用，旧旅程不增加障碍或通关门槛；线上版本不变。

## 机制与局限

- 南侧连接照相馆、工作棚的正常路线保持可达。缺口前不能到达北侧柜子，搭板后寻路与碰撞允许通过，原长板占地释放。
- 可提前搭板；但必须读过旧照归档标记才能辨认对应底片。短板试错没有库存损失或失败次数惩罚。
- 取走后柜中格子变空。归还移除库存，在摄影师关系、笔记、真实放大台纸层与片尾留下结果；也可以把底片带回家。
- 归档标记是作者定义的道具背面信息，不是假称生成的街景图画出了屋顶柜子。此环节仍为固定机制，并非每局新生成的调查章节，也没有证明整个游戏达到目标时长。
- 长短板及破损边缘是复用木纹与简化几何，属于可玩机制表现，后续统一环境美术仍需打磨。玩家理解与挑战是否足够有趣尚未由新玩家验证。

## 核心检查

54 项定向检查通过：空间、附近行动、Story Session、结局、照片桌面、完整委托和开场。新覆盖实际寻路开闭、普通出口、长板原地占地释放、短板失败、读标记／拿取／交还的唯一权威、丢回执重试、两种结局后果与旧旅程没有新实体。完整 `npm run build` 通过，资源校验和 Worker 启动通过。构建保留既有大 bundle 与历史 train 资源 URL 警告，不等同于新增资源丢失；本轮未发布。

发现并修复：可选规则最初使历史旅程出现未绑定动作；木板堆最初挡住工坊入口；木纹贴图因比例留白看起来像空框；照片背面动作被普通观察压住；归还底片的 DOM 层没有贴住真实桌面。最后一项改为 RPG-JS 独立精灵，支持位置来自桌子本身。

## 实际 renderer 操作

使用测试生成器＋普通权威行动准备到“旧照已显影并带走”的合成旅程，随后从旅程菜单进入真实游戏。夹具 id `02152a36-86a1-47e5-a5a8-d1965a9a01a9`，准备版本48，实际 UI 操作到版本60。前置48次操作是程序准备，不冒充从开场全程手动游玩。没有新增真实模型／媒体调用，也没有读取玩家存档。

实际完成：显影台读标记、沿门口上屋顶、先尝试未搭板的柜子、短板失败、搭长板、角色沿新通路走到北侧、开柜取物、原路返回、归还给初见的摄影师、刷新、看笔记与库存、街口离开、片尾显示通路和归还结果。叙事夹具为英文、宿主界面为中文；本轮不作为美国市场完整本地化验收。

390×844 检查开柜／取物，320×568 检查空柜／归还／刷新后桌面；使用浏览器视口模拟，不是真实 iPhone、触屏或声音验收。访客栏通过其自身关闭按钮收起，游戏生产代码没有隐藏外部扩展。实际片尾正常尺寸显示第6、7段对应屋顶通路与底片收存。

## 接下来

继续第二阶段的真实动态中段：把已支持的不同探索办法用于生成事件的后续调查，让发现改变解法和选择，而非继续添加固定跑腿或排序次数。屋顶支线是一个可用空间能力，不能据此宣布完整单人交付、时长达标或开始正式打包旧 RPG 技能。
