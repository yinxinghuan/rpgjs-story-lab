# AlterU 平台内试玩记录 · 2026-09-10

## 环境与范围

在用户打开的 Telegram AlterU Mini App 中，通过作者页 Create → Published → Play 实际进入两款游戏。操作与结果来自原生窗口截图及可访问性文本；这是 Mac 上的真实平台 WebView 验证，不是 iPhone 真机测试，也不是完整章节重玩。AIGram 的开发工具负责首次迁移，AlterU 用于平台试玩。

## 实测结果

| 游戏 | 有效操作 | 重新进入后的结果 |
|---|---|---|
| Carriage 07: A Light Left On（主游戏） | 移动到检修柜、打开柜门、拿起保险丝、查看行囊 | 从平台重新 Play，新游戏 frame 加载后仍为备用保险丝 ×1；电路20、照明10、信任0，未重复发放 |
| Rain Signal House（独立工作流验证短篇） | 移动到备件柜、打开柜门、取出备用电池、查看行囊 | 从平台重新 Play，新 frame 加载后仍为备用电池 ×1，目标仍为查看检修记录、断开旧回路 |

返回平台列表使用游戏底部作者入口 → Create → Published，再次 Play；观察到原游戏 frame 消失及新 frame 从 about:blank 加载，超过只关闭行囊面板的验证范围。两款 Published 条目均可见，试玩后各显示 2 Played。车厢平台画面没有外部访客栏，游戏地图、人物与交互可用。

信号房还提交了一次明确的观察输入“看看空柜里还有什么。”，等待后返回“柜子里的备用电池已经取走了。”。当前实现启用了真实模型调用，输出只选择当前设备作者目录内的 observationId；本次没有出现请求失败前缀。观察没有新增物品、角色或场景，不把此结果称为无限剧情生成。

## 结论与边界

两款游戏的首次迁移、平台入口、关键交互与重新进入后的持久状态验证完成。信号房存档为该浏览器 IndexedDB；车厢使用已授权的生产 capability。没有由此推断跨设备账号找回、iPhone 系统挂起或整章平台通关已通过。完整路线、权威恢复、遮挡和性能证据见当前工作流记录及各专题文档。

测试结束后系统锁屏，未能把界面切回主车厢；不影响此前已完成的操作和恢复结果。没有保存平台凭据、登录参数或个人数据。
