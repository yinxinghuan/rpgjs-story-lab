# 阿岚左向视频步态候选（2026-09-16）

目的：测试平台视频能否以已接受的四向站姿为参考，产出连续迈步，再使用现有制作页的处理内核去底、分帧和脚点对齐。只验证一种生成方法，不把成功返回的视频当作完整人物图集。

## 实际结果

- 原始参考为现有阿岚左向站姿，保持像素和比例，放入 288×512 洋红底；没有重画人物。
- 首任务在服务端读取 GitHub raw 参考时超时，终态失败。改用同 commit 的 jsDelivr 地址，下载核对 SHA256 相同后另建任务；没有重放终态失败任务。
- 第二任务成功，原视频保留在 `cdn-retry/candidate.mp4`。实际 576×1024、24 fps、121 帧，约 5.04 秒；有效图像在左上 288×512，其余为黑色填充。请求/任务/来源摘要见同目录 JSON。
- 视频保留了短发、绿衣、围裙与可见头顶的俯视关系。能看到腿部前后交替及摆臂，但一侧迈步显著大于另一侧，身体有水平漂移和轻微转动，像素边缘也比参考软。
- 按 4 fps 抽取 20 帧；去除有效画面外侧 3 像素的空背景编码边缘，再用 `prepareSpritePixels` 洋红连通去底，输出 256×352，脚点 128,328。没有缩放、镜像、重画或补出缺失肢体；原视频和提取帧均保留。20 帧均通过尺寸/主体不裁切检查，处理元数据与摘要见 `cdn-retry/preparation.json`。
- 代表帧 04、09、11 已逐张目检：透明背景与落脚位置可用作候选，但轮廓仍有少量颜色污染；04 的大跨步与09较小的反向步幅不对称。自动 bbox 对齐只消除平移，不能证明整段行走没有晃动。

## 准入与下一步

**未准入正式行走，未替换游戏素材，未发布。** 此次只有左向视频，尚无其他三向；尚未在真实 renderer 对这段候选做连续走动验收。不能用站姿补其他方向后宣称四向完成，也不能把静止逐帧检查说成步态通过。

方法已证明可以获得连续动作和可处理的关键帧。下一步先检验左向对齐后连续播放/实际移动的晃动与两腿幅度，再决定是否制作其余方向；如果仍滑步，保留原有站姿及已修正的老周运动，不为凑齐素材批量扩展。视频音轨未用于游戏、未作声音验收。

## 同游戏实景试走补充

随后在当前游戏增加仅限 `oldstreet-dev` 开发模式的 `?debug=1&npc_gait_trial=lan-left` 开关：四个站姿仍来自原素材，视频03–12组成10帧左向候选，RPG-JS按实际碰撞后路程切帧（20世界单位/周期、24单位/秒）。按钮只让洗衣店里的阿岚向左走24单位后停下，不能往右镜像、不能替代完整NPC活动；暂停/近处玩家停止迈步。普通入口和生产构建均不启用此候选。

CUA实际打开既有本地测试旅程，经工作棚已开院门到洗衣店，再切到390×844正常跟随镜头。通过访客栏自己的Close按钮关闭栏。连续六张截图捕获5.6、6.8、7.8、11.8、13.9、16.1单位时的video-2/3/5/6/8姿态，随后页面显示stand、24.0/24；脚底保持落在地面，身体与手臂确有动作，不是平移站姿。走动后点击人物并执行打招呼，角色由“系围裙的女人”变为已介绍的“阿岚”，交谈选项开放，现有旅程保留。

实景判断：此方向已能在目标尺寸看见迈步；反向腿摆幅偏小，循环接回原站姿略有跳变，不能宣称自然步态或四向准入。该有限测试支持继续验证另外朝向的视频来源，正式人物仍使用原站姿。没有新增模型/媒体请求、生产部署或iPhone实机验收。

接入时补齐三位居民共同的动态站位投射：人物图、碰撞和接近点共用偏移；活动者移动检查仅排除自己的身体，其他道具和家具仍碰撞。居民8项、空间/会话/家具32项通过，完整生产构建通过；实际dist不包含候选图集或测试入口字符串。UI静态审计没有此次源码命中，但全仓严格模式仍被65条历史dist目录内的第三方字符表命中，未将其标成整体通过。

## 本地复现

在游戏根目录运行，要求 ffmpeg 与 Node 22；不调用外部生成：

```sh
mkdir -p doc/oldstreet-lan-video-walk/cdn-retry/frames-roi
ffmpeg -i doc/oldstreet-lan-video-walk/cdn-retry/candidate.mp4 -vf 'crop=288:512:0:0,fps=4' -vsync vfr doc/oldstreet-lan-video-walk/cdn-retry/frames-roi/%02d.png
node --import tsx scripts/prepare-lan-video-frames.ts
```

`platform-gait-video-candidate.ts` 是可恢复的平台请求脚本，已有任务仅 `--resume` 同一请求；本地复查不运行该脚本。公共 API 未给出费用，不能把生成耗时当作费用。

## 其他朝向批次（2026-09-17）

三条新请求均成功返回原视频，参考图事先下载并核对与本机SHA相同。视频首帧分别正确呈现正面/右面/背面，因而不能把后续朝向错误归因于错传参考。右向在0.75秒改为向左，1.5秒旋转到侧后，3秒仍向左；背向在0.75秒侧转，1.5秒露出正脸且外貌改变，3秒再侧转。两者拒绝，不去底凑出步态。正向0/3秒大致朝前，1.5秒侧前倾转，继续保留待完整选帧，不宣称通过。各目录保存任务、原视频、抽查帧及review.json；没有追加同配方重试。

当前方法限制从“尚未试过其他方向”变为“参考首帧可以生效，但中间动作朝向不能可靠保持”。下一次若继续视频试验，应先用一条背向固定镜头、原地踏步的简单动作描述验证，不再批量重复这套多周期提示词。左向实景证据不外推到整个人物。
