# 图片准备误判超时修复

上轮主游戏在开发热更新后出现过 ART_IMAGE_TIMEOUT，重连成功。本轮检查确认该错误来自 DOM/SVG 图片准备，而非下载、Story Session读取或GPU纹理加载。

旧实现只等待 `HTMLImageElement.decode()` Promise，10秒后失败并清空src。在本地浏览器中用真实街口地面768×1152 PNG，单独模拟decode永不返回：3毫秒收到load且natural尺寸正确，1005毫秒仍被旧实现判为超时，1007毫秒因清空src触发error。本地故障页为缩短检查使用1秒超时，生产仍是10秒。

新实现同时接受成功load或缓存complete，并要求naturalWidth/naturalHeight均大于零；decode仍可作为完成途径。abort、损坏图片和真实停滞仍失败，结束时释放监听/定时器。GPU纹理依旧单独走Pixi加载，不能用这项修复绕过纹理/renderer就绪检查。

同样的回调停滞模拟，修复后1毫秒load、2毫秒ready，实际图片显示完整；这些数字只代表该次本地小检查，不代表游戏启动耗时或手机性能。6项图片准备及存档丢回执恢复测试通过，损坏图片、零尺寸、真正停滞与取消仍被拦截。

主游戏实际刷新恢复完成旅程成功，结局与推车/钥匙保持；通过旅程菜单切换到已有未完成的合住院旅程，背景和人物载入、操作恢复。未创建新游戏或改写存档事实。

这证明修复了已载入图片被未完成decode回调阻塞的情况，**没有证明上轮自然发生的超时必定由同一原因造成**。`_qa/art-loading.html` 是不读取旅程、不调用外部服务的局部故障检查入口，不进入生产构建。浏览器截图已直接检查，未另存文件。

后续实际从合住院出口走到街口，按需载入街口地面/屋檐并恢复操作；生产构建、9场景27资源SHA检查和Worker启动通过。
