# 档案工作间：动态调查链本地实证

范围：现有主游戏的开发分支。UI 本地基线之后的第二阶段增量；没有新增游戏或 UUID，没有线上发布，没有声称完整游戏或制作技能交付。

## 本次实现

- 新旅程 `letter-trail-v2` 在已生成的寄存索引、纸袋材料之后增加档案工作间。前两段真实已准入内容成为第三段生成上下文。
- 房间由地下室侧门连接。候选准备和准入不会传送玩家；必须实际走到门口进入，能够原路返回。
- 两种资料架布局、两处来源、四张事件卡。三条先后关系必须共同确定唯一答案，单处来源不足以确定全序；模型不能自行给“已完成”。
- 玩家走近两个资料架获得线索，在桌面还原顺序。错误可调整，成功后将结论加入旅程发现和尾声。后台保存生成实例、查阅状态和完成结果。
- v1 与此前无 campaign 的旅程保留原结束条件。新规则只属于显式新建的 v2。

## 真实页面发现与修复

1. 第一次开放新房间时，地图只出现热点、家具不显示。RPG-JS 在启动时登记事件，当时档案内容尚未准入，登记为空。现预登记稳定家具事件，在房间实际初始化时读取已准入布局；不同布局旅程切换重载单实例 renderer。
2. 点击资料架曾弹出“暂时没有别的可做的事”的通用空面板。现直接走近并查阅，使用具体“查阅记录 / 整理记录”行动名；仍有独立的自由输入入口。
3. 解谜成功的结论原先排在长面板末尾，320 宽时不可见。现用调查发现和正确顺序替换答题区，玩家直接看见结果。
4. 街区示意图新增档案节点和地下室发生重叠，现增加独立行，未知地点仍不提前显示。

## 实际浏览器操作

使用独立 `.data/campaign-map-playtest-20260917` 合成库及显式注入的 `campaignFixture`。检查点由 `_qa/prepare-archive-checkpoint.ts` 通过正常权威行动准备至地下室，不直接写剧情字段；这不证明之前房间的实际走动，本轮只检查新增环节。未读取真实玩家存档，未调用外部模型或生图。

- 中文检查点：准备原始记录 → 开放侧门 → 在地图走进档案间 → 查阅两处证据 → 提交错误顺序 → 得到可调整反馈 → 正确排序 → 保存发现 → 刷新恢复 → 从门返回地下室。之后切到另一旅程再切回，仍可回访已完成的结果。
- 家具修复后新建英文检查点，从尚未开放房间的状态启动，不刷新地完成准备和入场；确认首次进入已有两处资料架与桌面，位置与可交互点一致。
- 390×844：实际场景、三件家具、出入口、英文标题、展开街区图。
- 320×568：中文成功结果、英文线索/排序区滚动；关闭与核对按钮留在固定位置。自由输入能打开并输入英文，随后清空而未提交。未模拟真实 iPhone 软键盘。
- 访客栏通过扩展自己的关闭按钮收起，未修改游戏源码隐藏它。临时英文浏览器环境在检查后恢复。

## 尚未证明的部分与下一步

- 全部新链内容仍是合成夹具；真实模型三段连续内容的质量、不同旅程的有效差异尚未验证。没有把随机预设或当前夹具描述为真实生成结果。
- 必须完善材料、档案发现与带信回家之间的主线动机和因果。不能只因需要更长游戏就强迫玩家完成无关支线。
- 当前房间复用家具和铺地，美术氛围尚简陋，不作为质量基准；不会为这个内部环节做交接包。
- 45–60 分钟仍是设计目标，尚无实际时长证据。新玩家理解、iPhone 真机、声音听感、正式网络/账号恢复、集中双部署与 AlterU 全流程仍未完成。
