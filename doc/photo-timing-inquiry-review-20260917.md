# 照片拍摄时机调查：定向机制与真实内容检查

## 调整

提示词要求任意四个历史事件既合理又不能靠常识猜解不稳定，因此新调查改为一种明确结构：照片是在已知维修之前还是之后拍摄。程序提供两套成立的时序、分散在两处的证据和唯一答案；模型只命名照片／文件并选择支持的家具布置。玩家仍须查资料，不能从寄存条两端直接确定答案。

`photoTiming`随已准备的档案一起保存；只有档案排序完成后，照片来源才包含`capture.timing/workEvent`。后续生成及内容复核消费同一时机。历史已准入档案没有这个字段时保持旧行为；不重新生成、不迁移或给旧结局追加步骤。

这是一个可复用调查结构，不是任意情节因果生成，也不是新增完整章节或达到目标时长。物品特写、地图、来源位置和排序操作继续使用现有界面。

## 验证

- 16项定向测试通过：中英文、前后两种时机、两份资料缺一不能确定问题答案、存储恢复不重新抽样、一次有界修正、拍摄阶段传给照片生成，以及明确不兼容图片描述的拒绝。
- 其中包含默认生产planner→实际SQLite候选任务→重建任务服务→取回同一档案的代表性链路。准备完成不会自动观察或提前开放未读材料。
- 完整`npm run build`通过，包括TypeScript、空间合同、前端产物素材检查和Worker构建／启动检查。沿用已有资源解析及大bundle警告；本次没有更改资源路径。
- 两组真实英文合成链共8次平台叙事请求，无失败、纠错或重新抽样。输出全文见`campaign-live-20260917/photo-timing-1.json`；没有发送玩家存档或调用本轮图片生成。

真实结果一：Elm Avenue路灯换灯泡，照片在更换之前，描述聚焦路灯和玻璃灯泡。结果二：破裂水管维修，照片在维修之前，描述聚焦露出的水管。对象与拍摄阶段没有明显冲突。

人工复核保留的瑕疵：第一组描述把工作台和照相馆带进照片，并称灯泡是“original”，后者并非单凭照片可知；第二组补充了原材料未指定的铸铁材质，语义审查误称档案已指定铸铁。这些不改变谜题答案或状态，不能据此宣称模型语义审查可靠无误，也不再为普通细节反复抽样。

两组随机结果恰好均为before-work。after-work仅有确定性测试，本轮不宣称真实两方向覆盖。此轮未重新实走整条地图或生成PNG；此前普通入口完整真实生成→显影特写→结局→刷新证据见`campaign-live-journey-20260917.md`，不能把它算成新时机结构的完整实走。

## 下一步边界

默认新调查使用结构化时序；`--record-driven`继续保留不稳定的旧实验，历史夹具测试显式走该分支，不作为新默认的证据。保留代表性机制测试，停止同类批量抽样。后续整合版重点验证实际呈现、节奏与正式平台；本轮未部署线上。
