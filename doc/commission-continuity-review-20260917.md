# 连续生成真实复测（2026-09-17）

## 结论与范围

两组全新链的文字生成已实际测试，发现并修正提示示例串入照片题材，以及三个候选主题实际上永远选第一个的实现问题。没有新增媒体生成，没有访问玩家数据，没有浏览器全程试玩，没有发布。UI本地基线沿用上一轮；本次是第二阶段的内容连续性工作，不能作为完整动态章节或45–60分钟体验通过。

## 修正

1. 删除照片提示中的具体木板例句，要求以已保存档案的实际对象和材料组织照片主体。
2. 复核提供档案事件和照片主体的原文依据，分别比较对象与材料；不能只因同属街道维修就放行。检查项与总 verdict 矛盾时拒绝，保留原重试/失败恢复流程。
3. 寄存主题抽取独立于显示顺序，不再固定使用 subjects[0]。18种主题/行序组合各自仍要求两条线索唯一交集，保存后不改变。

## 验证

- 30项定向测试通过，覆盖记录编译、权威准备/提交/恢复、委托和照片计划/媒体恢复；这不是全游戏所有路线的测试。
- `npm run build` 通过，包括 TypeScript、空间校验、资源完整性与 Worker 构建/启动；既有大包和旧音频引用提示仍在。
- 本轮无布局/美术修改，沿用既有视觉证据，不冒充重新做过 renderer 或真机验收。

## 还差什么、下一动作

当前生成仍以同一套排序机制配不同文字为主，不能满足两份调查行为确实不同的旅程验收。应停止通过更多提示词样本证明玩法，下一步在现有可移动物件、工具、现场照片与出入口能力中设计并实现一个不同于排序的完整调查环节，让玩家的发现决定实际操作或探索路线，再做一条代表性实际游玩。观察文字的事实/推断边界随该环节一起收敛；不添加一组更严格但频繁误拒的语义规则，也不通过更多便笺和强制往返增加长度。

仍欠完整内容量、实际节奏、真实iPhone/音频/平台综合验证和第三阶段旧RPG技能改造。保持生产开关关闭与旧存档兼容。
