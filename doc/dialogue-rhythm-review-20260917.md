# 对话分步呈现 · 试玩反馈修正

用户指出 NPC 台词与回答按钮过于接近，点击后容易误认为没有响应；随后明确要求先收起选项、出现回答、再出现下一组选项。

## 调整

- NPC：人物名、左侧引文线与 18px 衬线台词，取消纸色按钮形状。
- 玩家：等待时右对齐显示刚选的话与状态；选择区有“你的回应 / Your response”与纸色按钮。
- 回应先淡入 180ms；最后一页台词出现 900ms 后，选择区再淡入 180ms。多页正文先读到最后。等待区保留选择所需布局位置，避免按钮出现挤动正文。
- 新回应与翻页将阅读区回到顶部；不移动地图。小屏对话高度上限提高，320×568 可见本次短对白及两条常用回答，额外内容仍可滚动。
- 减少动态效果禁用淡入；请求、恢复、关闭与权威存档不增加动画等待。

## 实际验证

复用本地 55678 合成测试旅程，从街口进入照相馆，走近诺拉并正常介绍、翻页、选择话题，使用既有预设回应，没有新增模型或媒体生成。

真实 DOM 观察记录：点击前为选择态；39ms 显示玩家话语与走近状态；45ms 等候回应；76ms 出现 NPC 台词且选择不可见；981ms 出现回答按钮。即台词先于选项约 905ms。台词出现与按钮出现时正文 y 坐标均为 427.82px，地图 transform 全程一致。探针只观察本地 DOM，已自动停止并清除临时结果。

截图在 `_qa/ui/dialogue-rhythm-20260917/`：390×844、320×568、844×390 的 platform-layout；没有横向溢出，横屏回答按钮高 44.4px，短横屏保留两栏。初次320宽发现选项被面板高度截住，调整后同一状态重新截图，两条回答可见并实际点击成功。减少动态效果下台词及选择动画均为 none。

8项现有对白与分页测试、完整 `npm run build`（含 Worker 启动检查）和公开凭据扫描通过。最终构建 CSS 已包含小屏对话高度修正。UI静态审计的65项提示全部来自13个历史 dist-* 目录的生成 bundle，涉及第三方组件/实体表；本次改动的源文件没有命中，不据此修改历史输出。另保存了默认桌面 external-guest 截图；访客栏仅使用自身关闭按钮收起，生产加载代码没有改动。

本次是局部交谈体验修正，不代表完整新玩家理解验收或真实 iPhone 测试。开发版供继续反馈，不自动推进技能制作，也未发布线上。
