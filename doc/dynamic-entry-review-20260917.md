# 动态委托的界面衔接验证

本轮属于系统 UI 第一阶段，检查“目标 → 操作 → 可见结果 → 下一步”的连续性，不重新遍历整条路线，也不代表完整游戏的节奏与内容深度已经达标。

## 调整

- 共用放大台与显影台把当前阶段的主要操作放在回看日志、自由输入之前；后台组件仍保持挂载，收起界面不会重启任务。
- 准备完成的按钮明确叫“打开暗房门”。成功后收起互动面板，短暂告知从照相馆后门进入；人物停留原地，玩家仍通过自然出入口进入。
- 已有具体档案线索时移除重复的流程解释；保留准备、失败与重试反馈。

## 实际操作证据

本地 55673，新建合成 v3 旅程。`commission-playtest-progress.ts --seed-synthetic --before-photo --journey=<合成旅程>` 使用正常权威动作预置到已核对档案的放大台前（版本38）。之前的动作不是浏览器实走证据。之后通过实际游戏界面完成：

1. 主动查看放大台：寻找相关旧照和回看外借日志同时可用，当前任务在前。
2. 提交照片线索，准备就绪后打开暗房门；面板关闭、自然门出现、人物没有传送。
3. 走近暗房门，以右下按钮进入；走近显影台，以右下按钮查看。
4. 冲洗照片、调焦与曝光，根据清晰度提示确认；选择带走，随身目标更新为回家或继续探索。
5. 刷新恢复后照片仍在行囊，目标不丢失，已完成的准备任务不再出现。

390×844 检查请求及自然门反馈；320×568 检查特写全部控件、可滚动的结果选择、行囊目标。截图在 `_qa/ui/dynamic-entry-20260917/`，均为关闭外部访客栏后的 platform-layout。照片复用之前保存的平台 PNG，文字使用本地夹具；没有本轮在线模型或媒体生成，不声称验证真实生成等待时长。真实 iPhone 软键盘及首次玩家理解仍未验证。

18 项扩展、显影、媒体恢复和准备状态定向测试通过。完整构建通过（9场景、27资源 SHA 校验、Worker 启动）；公开凭据扫描通过。保留既有构建警告：大 bundle、旧列车图片及音频引用未在编译时解析；不是本轮新增，生产发布前仍需按实际入口确认。
