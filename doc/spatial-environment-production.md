# 空间环境制作方式

本文件记录现有主游戏积累的制作选择，服务后续RPG场景制作；不是切片交接包，也不表示动态地图能力已经交付。

| 场景需求 | 优先方式 | 原因 |
| --- | --- | --- |
| 固定剧情地点、主要探索空间 | 整张静态环境或同图分区 | 连续光影和生活痕迹更自然，减少拼贴成本 |
| 动态创建、可重组房间、迷宫、地图类小游戏 | 已准入小图平铺与模块组合 | 可先产生合法布局，地面/墙/通道按布局装配 |
| 需要动态布局又要氛围 | 平铺基础＋稀疏装饰层＋独立事件 | 在复用与场景变化之间平衡，无需每次生成整张大背景 |

用户2026-09-17明确保留小图平铺这条方法；它不是失败方法，也不是所有固定场景的默认解法。

## 共用合同

1. 先定义人物尺度、通行净宽、出口与碰撞，再选择图片。地板每一块砖/木板的实物尺寸与像素颗粒分开校准。
2. 静态图只承载不会变化的环境；门开关、可搬箱子、拾取、解谜状态、NPC不能烘焙进去。视觉通路与真正可走区域一致。
3. 平铺入库要检查九宫格接缝、比例、重复节奏；墙/道路模块还需边、角、端点、连接规格。变体可以改变表面细节，不能悄悄改通行宽度。
4. 装饰按地点积累在边缘/墙脚，避开入口和线索。会挡路的物件必须注册同一碰撞；平面污渍、落叶不引入障碍。
5. 动态布局需保存布局/种子和素材版本，返回时还原原地图；生成失败保留已经可玩的基础空间。只有有结构、有合法出口、有基本表现的房间才能进入。不能先把玩家丢进虚空等待整图。
6. 已认可的是方法和可接受瑕疵范围，不是每张旧候选。当前素材库candidate不会因本条决定自动变成admitted；不合比例的旧木地板不得作为生成参考。

## 当前实证与尚未实现

已实证：修表铺整图分区、洗衣店裁切地面、院落整图地面、旧木/石地面平铺、独立门/箱组状态与共享空间布局。现有 `src/material-library/catalog.json` 记录材质元数据和准入状态；可复用制作合同已在build-spatial-story-game技能中，具体样本不等同通用视觉基准。

尚未实现/验证：玩家动态生成迷宫、程序化房间拓扑、模块墙体自动拼接与迷宫存档恢复。先完成当前完整单人游戏，实际需要此类场景时再按本流程验证；不为记录方法另开独立游戏或立即扩充大批材质。
