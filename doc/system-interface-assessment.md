# 系统界面评估与调整顺序

## 目标与边界

玩家以地图探索为主要活动。保持 B 俯视、满屏跟随相机、点击移动和摇杆、当前纸色/暗色风格。信息结构沿用 A，临时提示吸收 B；本轮不重新选择美术风格，也不扩展故事长度。用户指出的附近弹窗只是一例，评估覆盖所有主要操作。

已有 `interaction-layout-contract.md` 继续约束实现；本文件补充整体判断及下一批工作，不把下述设计决策写成已实现。照片摆放等未完成玩法增量暂不作为本轮 UI 收口的前置条件。

## 评估方法

1. **任务走查**：沿“进入/续玩→找目标→移动→互动→看结果→继续探索→收尾”检查目标、动作、结果和返回。重点检查界面之间的连接，而非逐条重复剧情路线。
2. **显示必要性**：每项信息归入常驻、情境出现、主动展开或事后回看。没有当前用途的内容不占地图；重要线索不能只出现在转瞬消失的提示里。
3. **一致性检查**：相同操作使用相同动词与返回逻辑，地图目标和行动按钮指向同一个对象；不同任务保留各自适合的表现形式。
4. **容量与兼容检查**：短文本不代表完成。检查长英文/中文、多个选项、多条发现、多段旅程、慢请求、失败、短横屏和手机输入。尺寸模拟与真实 iPhone 键盘分开记录。
5. **代表性验证**：每类机制选一个代表状态及一个内容压力状态，修复后复验相同状态。不为证明 UI 重走所有路线；自动化和作者走查不冒充新玩家理解测试。

## 响应式结构

- **竖屏探索**：地图为主体，顶部轻量工具，底部双手操作；情境面板在控制区上方，标题/关闭稳定，正文及选项内部滚动。
- **短横屏和宽屏**：不能只把竖屏整体缩小。优先把情境阅读区放到一侧并限制宽度，保留足够地图与可触达控制区；具体断点根据运行检查确定。专注特写仍按任务需要使用居中、可滚动内容。
- **文字编辑**：可用高度缩小时优先保留输入、发送和关闭；完整前文可滚动回看，地图不因普通面板开关重排。真实软键盘表现需要实际设备验证。
- **共同约束**：功能目标至少44×44 CSS px；长标签换行或显示短动作名并保留完整可访问名称；不以缩小所有字号解决拥挤，不把访客栏计入平台内安全区。

## 执行顺序与完成标准

1. 先收整菜单/工具的信息归属与探索界面的视觉主次。菜单要能容纳不断增加的旅程，主地图不随内容量增加常驻元素。
2. 再统一对话、物件、特写、随身的阅读与行动层级，检查代表性长内容以及返回链。保留任务差异，不机械共用一种弹窗。
3. 按初次加载、后台准备、操作提交梳理等待/恢复，并做短屏、横屏、键盘焦点及双输入交叉检查。
4. 沿一条代表性连续体验验收上述结构；每种新机制只补缺少的状态，不反复全路线回归。完成后再推进动态中段，最后沉淀/更新制作技能。

本轮已做：源码结构核对；本地新建测试旅程（保留原有旅程）；390×844纯探索、长旅程菜单、结尾，以及568×320随身的实际界面观察。未调用生成服务、未发布线上；尚未据此宣布整体UI通过。真实 iPhone 软键盘、新玩家理解与正式平台整合仍单列未验证。

菜单调整前证据：`_qa/ui/system-assessment-20260917/platform-layout-menu-390-before.png`。通过外部访客栏自身的关闭按钮检查平台内构图；未修改生产页面隐藏访客栏。

## 第一批实现与复验：菜单和探索工具

已实现：顶部第三入口改为“菜单”；游戏设置/操作帮助与旅程目录分区，只有进入旅程区才读取目录。旅程列表独立滚动，关闭与分区切换始终可达，另开探索及保留旧进度说明在列表外。结局的“查看旅程”直接打开旅程区。常驻工具改为暗底浅色线图标，无目标行动按钮降低强调但不移动位置，实际可执行按钮保持纸色层级。

短横屏初查发现新建区被挤出可见范围，已用两栏布局修复：左边列表，右边另开探索。仅对宽度至少540、高度至多480的菜单使用，竖屏仍上下布局。删除目录顶部重复解释，行内“当前/继续/已完成”承担状态说明。

本地实际复验：390菜单前后对照；320展开操作说明及十条旅程；568×320横屏列表和另开入口；声音开/关/恢复；切入既有已完成合成旅程，片尾→查看旅程直接到对应分区，再续玩本轮测试旅程；Escape关菜单后焦点回菜单按钮、摇杆恢复可用。原旅程没有改写，未发起生成请求。证据为同目录 `platform-layout-*-after.png`、`platform-layout-controls-320.png`、`platform-layout-journeys-320.png`、`platform-layout-journeys-landscape.png` 与 `external-guest-390.png`。

完整构建通过（9场景/27资源SHA、Worker启动）；公开凭据扫描通过。UI静态扫描仍报告历史产物/旧代码的字符图标待审项，本次菜单两个文件无命中，不能据此声称全项目静态UI门禁清零。既有构建体积、旧列车资源引用警告仍在。此为第一批结构调整，后续继续对话/物件/随身的内容层级和输入等待，不宣布整体UI或完整单人目标完成。

## 第二批实现与复验：阅读与行动的层级

随身新增“当前”分类，默认显示目标和准备进度；四个短分类与关闭固定，内容统一在一处滚动，不再由长目标挤压物品/发现。物品用途直接显示，发现/人物按标题展开完整原文；切分类滚动归顶。没有改动已知人物、物品或事实的来源。

交谈先保留现有可执行行动及前两个话题，“其他话题”和“分享发现”分组展开。执行后收起展开组，原回调继续提交权威行动；不减少选项、不增加生成调用。自由输入展开后聚焦，短屏编辑时暂时隐藏话题组，保留输入/发送与原右下探索返回。

本地实际：恢复既有合成照相馆旅程，查看长目标、准备就绪回访、物品、15条发现、人物；320分类/发现与568×320长发现可读；真实地图走近诺拉→右下交谈→询问楼梯→展开分享调查→回应→其他话题回问，人物正确记得刚才的调查。320实际滚动可到达扩展话题，标题/关闭保持；390×340模拟可用高度缩小，输入聚焦、取消后恢复探索。未发送自由文本、未调用外部模型或媒体。证据在 `_qa/ui/content-hierarchy-20260917/`。

11项对白分页/随身数据检查、完整构建通过。真实iPhone键盘、整体玩家理解仍未验证；普通物件的主要行动继续直接显示，不统一折叠进“更多”。下一项集中等待/返回及短横屏情境面板，避免把这轮改版扩大为全部UI完成。

## 第三批实现与复验：等待、恢复和短横屏

当前操作提交后立即显示对应处理状态，3秒后补等待说明；不再继续把旧回应当当前结果。未确认错误只显示恢复说明和重新连接，隐藏失效旧行动及扩展操作；不改权威恢复协议。照片候选已生成但图片尚未下载时，明确显示正在载入及原显影台回访位置，按钮标明载入中；下载失败仍只重载已有图。

568×320实景发现标题/控制区保留后正文仅余两三行。现改为主动互动时暂隐顶部导航、回应/行动双栏独立滚动，返回后恢复导航；竖屏不变。每次新回应/翻页/切目标均归顶两栏，输入模式回单栏。地图相机不因面板尺寸变化重排。

本地测试仅用既有合成旅程与预设话题：延迟2500ms时出现3秒等待提示，响应回来恢复行动；请求前断线后仅保留恢复入口；重新连接返回同一照相馆、诺拉位置可继续交谈。1280×720与320×568恢复画面、568×320对白在 `_qa/ui/wait-layout-20260917/`。网络模拟已撤销、临时页关闭。此处没有模拟“服务器已经提交但响应丢失”，不混称为该机制验收。8项本地/扩展恢复及恢复文案测试通过。

照片下载文案完成代码检查，本轮没有单独复现下载中截图；真实iPhone软键盘与新玩家理解仍未验证。后续只补整套结构的代表性连续走查及未覆盖状态，不逐条重复剧情路线；整体UI及最终单人游戏尚未宣布完成。

本批完整构建通过：9场景、27资源SHA及Worker启动检查。公开凭据扫描通过；全量UI静态扫描仍被历史产物/旧代码字符图标项阻止，本批三个源码文件无命中，不将其记为全项目扫描通过。保留既有bundle体积和旧列车引用警告。

## 连续体验与本地结构阶段收口

本轮从照相馆经自然门到街道→地图查看工作棚路线（无传送）→修表铺→抽屉主动拿放大镜→随身回看用途→主动调查空小格→刷新继续，沿用既有合成旅程。照相馆对话、材料/显影特写、菜单、片尾等已有前三批及对应机制证据，不重复整条故事。新增证据在 `_qa/ui/continuous-structure-20260917/`，没有新模型/媒体请求。

首轮街道长距离走近曾提前中断，后续同目标可正常进入；路径算法实算终点与门距离32（要求严格小于54），155帧正常完成，未证实几何错误。保留此观察，后续真实输入验收如复现再定位取消来源，不虚构修复。

源码发现自动目标每帧按最近距离重选，已补8逻辑像素切换余量；明确点击物件后优先该物件，场景/投影消失/离开有效范围均不能越界保留。目标半径与空间绑定共享常量，服务端规则未放宽。11项目标选择/上下文行动检查通过；实际抽屉→小格的按钮和主动面板对应，刷新后空抽屉状态保留。

本地结构改造进入维护状态。接下来恢复第二阶段：完整动态中段的空间调查、不同解法与可持久化选择后果，已有照片去向增量按该目标收束，不能靠重复排序/往返凑时长。新增内容直接遵循统一面板/输入/等待合同。真实iPhone软键盘、新玩家理解、正式平台网络验收保留为后续整合阶段项；不是整体单人游戏交付完成，也不提前打包技能。
