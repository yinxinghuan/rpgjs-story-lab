# 平台美术生产链验证计划

2026-09-11，依据用户对内置生图工具与创作者/游玩实际能力不一致的纠正。此项前移为下一阶段首要工作，在继续批量生产原作区域、人物与设备之前完成；UI 精修和多人仍后置。

## 当前事实

- 当前 B 方向的部分场景、人物与设备候选由 Codex 内置 imagegen 生成，用于验证相机、比例和视觉方向。它不是平台用户可以调用的正式生产能力。
- 本工程已经接入 AlterU 公共媒体客户端和旅途画页任务恢复，但此前两次真实画页请求均返回 PROVIDER_REJECTED，未得到可评审结果，正式画页入口关闭。这既不能证明当前服务整体不可用，也不能证明列车 B 风格能够量产。
- 当前素材只是目标样本，尚不是经过平台媒体服务验证的生产质量承诺。图片格式为 PNG 不代表具有真实 alpha。

## 共用链路

创作者描述/玩家授权的内容请求 → 世界和视觉合同 → 媒体任务计划 → AlterU 媒体服务 → 候选验证 → 存储和版本登记 → 同场景渲染验证 → 激活。

制作期和游玩期调用同一平台媒体边界及同一候选验证规则，不依赖 Codex、GPT6 工具权限、本机脚本或人工修图。模型供应商及版本调整由平台媒体服务负责。自然语言由应用侧导演转换为受约束的英文生成提示，用户不必会写提示词。当前接口 edit 只有一个公开 HTTPS 参考，不假定它支持独立多参考/多身份输入。

## 执行顺序与通过条件

1. **真实服务先跑通一张**：用现有公开、已授权的项目参考及合成内容，确认 text/edit 可用路径，记录输入、服务任务 ID、响应、耗时和实际文件。不反复重试被明确拒绝的相同请求。失败时定位请求合同/参考/服务原因；不得以替换内置生图工具的结果冒充服务成功。
2. **三类素材质量对照**：环境背景、四向三帧角色图集、设备状态图各最多三个候选，第一批总上限九张，包含第1步样本。提示词可按平台能力调整，每次修改留痕；不要求随机生成器逐像素复现，但必须满足已认可 B 方向的角度、尺寸、人物比例、清晰度、状态一致性和可玩要求。角色检查真实透明、边缘、十二帧角色身份/四向/步态与脚底；设备检查各状态形状、尺寸及锚点；地图检查背景与模板几何/碰撞一致。每张记录人工修复次数、可用率、耗时和服务实际提供的费用；服务没有费用数据则记录未知。九张只能作为可行性样本，不代表长期生产可靠性。
3. **在同一个游戏里换入实测**：并排保留现有样本，实际替换通过的背景、角色和设备，在同一 RPG-JS 地图测试行走、碰撞、遮挡、设备变化及 320×568/390×844。只对通过的类别开放生成能力，不以一张背景成功推断动画图集也可用。
4. **创作者自助闭环**：无本机和内置工具参与，用创作者入口从主题描述生成一个最小场景、角色和可互动设备，经历等待、失败重试、候选预览、激活和发布版本。此最小实例留在现有项目，不另建验证游戏或交接包。
5. **游玩期闭环**：先开放非关键特写/旅途插画，然后测试有模板约束的物件或身份变化；个性化先用一份普通人和一份无脸/非人合成参考另作有界测试。新角色或新区域须在准备完成并通过表现检查后才进入可互动世界；等待时保留旧场景与可用行动。已激活资产写入存档版本，刷新不重画，迟到任务不能覆盖新进度，重试不重复计费或结算。不能承诺首次实时生成人物图集/地图无等待。

## 质量不足时的处理

先确定是否可通过提示、单参考、尺寸及可部署的标准处理改善。需要去背景、图集拆分或对齐时，必须成为创作者和游玩链路可调用的能力，验证自动化边界；本机人工处理只能作为研究证据，不能标记自助生产通过。若服务模型无法稳定产出相应类别，使用已准入素材库/模板组合，暂不开放该类别的全新实时生成；或由平台服务维护方评估统一升级生成能力。不得把未确认可用的 GPT6 图形 API 当作既定依赖，也不静默降低已认可的视觉基准。

通过以上服务样本、真实替换及自助闭环后，才继续扩展大量原作素材并固化面向用户的制作工作流。原有规则、存档和渲染开发成果继续使用，当前正式游戏不受候选替换影响。

## 第一批实测结果（2026-09-11）

已通过公共媒体服务发起五个有固定 request ID 的合成请求，五个均成功，约 9.7–13.7 秒；费用接口未提供，不能估算实际扣费。输入、原始 PNG、任务结果、摘要及逐项判断保存在 `platform-art-candidates/20260911/`。同请求重放与任务查询返回同一任务和素材 URL；这验证任务身份恢复，不等于独立核实账单。

| 类别 | 实际结果 | 准入结论 |
| --- | --- | --- |
| 无参考背景 | 有画面，但车体长度、地面占位及轨道透视偏离模板 | 拒绝 |
| 单参考背景变体 | 同地图检修点、车体阻挡和人物落点实测通过；偏暗、细节更平滑 | 可继续实景研究，未达到生产质量持平 |
| 新角色四向图集 | 新服装可生成，但侧面/背面未遵循，且 RGB 白底 | 拒绝 |
| 原角色换色图集 | 四方向改善，但棋盘格被画进 RGB | 拒绝 |
| 设备三状态 | 状态和大体角度可辨，但 RGB 白底、基线未按要求对齐 | 拒绝 |

真实透明检查解码了全部图片，三个角色/设备候选均没有 alpha 或 tRNS；未使用本机修图补救。背景候选仅进入同工程 preflight 对照页，正式 cloud/Pages 不包含它。桌面与 320×568 实际画面和行走已检查；390×844 DOM 尺寸/落点经缩放补偿核验，截图工具出现缩放留边，不能将该尺寸的构图评审标记完整通过。198 项自动化检查通过。

下一步优先解决**可部署的真实透明处理和角色四向/状态锚点合同**，同时完善背景亮度与细节保持；不要仅增加同类重抽次数。剩余四个候选额度是上限，不是必须消耗的次数。背景、角色、设备分别准入；创作者自助闭环和游玩期激活仍未完成。现有素材继续作为质量目标，不能用本批五张成功响应宣称平台已能稳定量产同等游戏美术。

## 浏览器制作入口实证（2026-09-11）

同工程增加 `?create_art=north-cape`，在 preflight 用浏览器直接调用公共媒体客户端，持久保存原请求/任务、字节与历史候选。第六个有界请求 `7ec82edb-2fdf-4c90-9461-99f908531729` 在 localhost 实际返回 `ORIGIN_NOT_ALLOWED`，没有服务任务 ID 和新图片；刷新仍显示同一失败，并禁用原失败状态下的无效重生成。未改变或伪造浏览器 Origin，未改用去掉 Origin 的代理绕过。原先五个成功样本结论保持。

另用先前已成功的平台背景进行真实样本载入，明确提示非本次生成；浏览器保存→刷新→同地图试走→左侧检修/车体阻挡→返回制作页→390右侧检修通过，320/390 表单和地图无横向溢出。此前390截图缩放的未决项，在本次 DPR=1、实际390×844下完成复查。206 项回归、三种构建和媒体集成检查通过。UI 静态扫描只报构建依赖的文本符号，未报告本次源码功能图标问题。

只读任务请求附带正式站点 Origin 返回200，为下一步部署验证提供线索，不能代替真实正式来源的浏览器 POST/下载/刷新测试。下一步在现有游戏受支持的部署来源验证完整创建链，继续解决透明、方向、锚点和质量差距；不把“已有样本可载入”或“任务GET成功”算成创作者自助生成闭环完成。
