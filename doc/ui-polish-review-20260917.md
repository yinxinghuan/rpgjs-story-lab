# 交互与 UI 首轮实景审查

检查版本：`7e29e89` 本地实际游戏，保留既有合成测试旅程。此次查看街口、照相馆入口及首次招呼，未运行新的模型请求。范围是界面发现，不是完整验收或新的风格定稿。

## 实际看到的问题

1. **行动入口重复**（390×844，街口）：底部“当前行动”卡片包含合住院按钮，右下角同时出现同名按钮；卡片还常驻“已恢复旅程”与“随身：无”。静止探索时占用地图却没有增加决策信息。优先合并到一个明确主行动，恢复提示短暂出现，空背包不常驻复述。
2. **对话选项被正文挤出首屏**（390×844 / 320×568，照相馆）：人物介绍与第一句对白同时出现，下一步话题在 390 下只露出部分，在 320 下完全位于可见面板之外。DOM 中存在按钮不代表玩家自然发现。需要短对白节拍、稳定选项区与可辨认的继续/离开，不以更小字体压入长文。
3. **选中对象与就近按钮不一致**（照相馆门内）：选中远处人物后，卡片显示“打个招呼”，右下角仍为“街口”。两者规则有区别但没有清楚表达。应统一玩家当前意图与行动目标，允许取消走近，不能让两个入口暗示不同下一步。
4. **入口构图出现大片场景外区域**（390×844，照相馆入口）：人物与房间集中在屏幕上半部，下方深色区域较大。需核对房间边界、相机跟随与面板预留空间的共同作用，在保留满屏放大感的前提下改善，不直接缩小人物以塞完整张图。

## 下一轮实现与验证

先处理上述行动/对话的结构问题，再统一字体、图标、面板与动效。不重新选 A/B/C，不扩展调试功能，不改玩家已有事实。每次只复验受影响状态：街口选择出口、人物招呼与后续话题、退出交谈恢复走动、窄屏输入键盘、安全区和加载恢复。英文长选项尚未检查，需要纳入。

当前只有实景问题观察；没有声称界面已修好、玩家理解已验证或手机实际触控已验收。完整技能制作继续置于修整之后。

## 本地实施与复验

- 已将主行动统一为显式选择优先，探索时撤去重复行动/空背包常驻行；预设话题和独立的自由输入展开入口保留。实际照相馆点击楼梯话题得到许青的短对白；结束交谈后面板收起、右下角恢复交谈按钮。
- 320×568与390×844浏览器检查短对白、可选话题和自由输入。输入展开时可滚动，未模拟iPhone软键盘，不能声称真机键盘已通过。旧旅程的许青身份没有被改成诺拉。
- 使用现有已完成合成旅程播放7段尾声；无需重新跑整条故事。实际确认照片归还、老周钥匙未还、诺拉后续等内容来自这份结局。暂停/上一段/继续/跳过/重看/查看旅程可操作，可重新选择未完成旅程。
- 首次实景发现HUD的22px SVG规则影响片尾人物，并有邻帧露边；已独立覆盖艺术图尺寸、添加单帧clipPath，随后检查主角和照片镜头。按钮采用尾声专属规则，避免继承探索页白底和footer间距。
- reduce模式手动逐段显示、取消图片倾斜和自动播放；320×568实景通过。图片加载失败仍保留文字回顾。截图在当前工具对话中，未写成仓库内图片证据。
- 本地测试19项通过，最终增量完整构建通过，9个原场景/27个资源SHA校验与Worker启动检查通过。对改动源文件执行UI静态扫描无图标/emoji命中；全目录扫描会命中历史dist，不据此宣称全项目零命中。

仍待：英文真实长文布局、iPhone键盘与触控、相机边界留白、声音收束和完整代表性体验链；本轮不是最终UI验收，不制作交接包、不追加小版本线上发布。
