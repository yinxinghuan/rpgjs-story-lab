# 便笺副本与原件归还

## 玩法与边界

在现有调查旅程中增加一条可选解决方法：借走便笺 → 走到照相馆放大台抄录 → 回原所在地归还。便笺原本在放大台时可以就地抄录。玩家也可以只带原件、只记住发现，或改变未结束旅程中原件的去向。副本让家人获得可携带记录，原件可以留给后来的访客；代价是实际操作与往返，没有新增金钱/计时/数值奖励。

副本是已观察内容的固定文字抄录，不是生图，也不声称生成了新照片。原件/副本的库存、知识、地图纸层与结局分开保存。复制不自动归还，归还不删除副本，重复回执不重复领取；旧已完成旅程仍保持原样。使用既有 Session 和家具，不新建游戏或后台，不新增强制结局条件。

## 核心检查

29项档案、campaign、Worker检查通过。两种放置地点都覆盖：抽屉原件必须实地带到放大台；台上原件可以留下并就地抄录。断言错地点不能复制/归还、未观察内容不提前可用、客户端正文不改变副本、同一请求恢复、重复复制拒绝、原件回放、保存恢复、分享记忆和结局区分。UI基础检查、API base检查及完整构建通过。

## 实际游戏

继续同一桥板合成旅程，副本新增部分没有调用模型或媒体，也没有重建存档。390宽从修表铺经街口进入照相馆，点击放大台后实际走近并抄录，背包同时显示原件与副本；320宽走回修表铺，选择放回原件，纸层恢复，刷新后背包只保留副本。截图位于 `_qa/ui/field-copy-20260917/`；外部guest栏通过正常关闭按钮收起，生产脚本未改，非实体iPhone测试。

实际发现并修复：有便笺抄录操作时，放大台仍提示“需要照片夹”；附近便笺操作替换后，会隐藏原家具的放大镜按钮。现按当前动作显示提示，并在面板保留原有可执行操作。副本说明也随原件在手/留在原处变化，不用永久警告代替状态。

随后沿街口正常结束同一合成旅程，320宽片尾第9段明确记录带回手写副本，第10段记录原件留在旧街；已保存两张结局截图。没有为结局注入状态或跳过主线条件。

## 剩余

本变化提供了真实的第三种处理办法，但仍只是现有调查的小段内容，不是新的完整动态章节。没有证明往返本身有趣或达到目标时长；后续需要把事件与空间难题组成完整中段，并做一次代表性整体验收，停止围绕单份便笺继续扩张。线上版本保持不变。
